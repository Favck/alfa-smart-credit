# Django ↔ неизменённый ML-сервис

Папка `ml/` целиком взята из коммита `50af371` и не изменялась при интеграции.
Не меняются модель, веса, обучение, HTTP-обработчики, Dockerfile и requirements.
Адаптер находится в `backend/api/scoring.py`, процесс заявок — в `pipeline.py`.

## Запуск и границы

`docker compose up --build` поднимает ML, Django и Vue. Наружу ML не публикуется.
Вне Docker: запустить исходный ML на 8001 и задать Django
`ML_BASE_URL=http://127.0.0.1:8001`, `ML_TIMEOUT_SECONDS=2.5`.
Для LightGBM под Windows нужен путь без кириллицы; Linux/Docker использует `/app`.
Нельзя переобучать модель или менять её файлы для устранения различий контрактов.

## Контракты

- Vue вызывает Django `POST /api/v1/scoring/pre-predict/` с параметрами продукта.
- Django добавляет собственные request_id и preview application_id, реквизиты
  компании, стаж и синтетические сведения БКИ; браузер не может подменить их.
- Django вызывает ML `/api/v1/scoring/pre-predict` или `/api/v1/scoring/evaluate`.
- Проверяются структура ответа, диапазоны и совпадение request_id для evaluate.
- Размер ответа ограничен 512 КиБ, таймаут 2.5 с; ошибки дают ручное рассмотрение.
- Модель поддерживает investment и до 120 месяцев, сайт — три продукта и их
  собственные диапазоны до 60 месяцев. Django валидирует и рекомендации, и ввод.

## Важные особенности исходной модели

- ML всегда использует аннуитет при ставке 22%, включая овердрафт.
  Django не изменяет вычисления ML, но платёж для интерфейса считает по
  демонстрационной ставке выбранного продукта. Для овердрафта платёж null.
- approval_probability_percent в исходном ML равен 100 − PD. В интерфейсе это
  прямо обозначено как оценка модели, не гарантия или калиброванная вероятность
  фактического одобрения кредитной политикой.
- При стоп-факторе модель возвращает score=null и служебное PD=1; клиент получает
  понятную причину, сотрудник видит оригинальные поля и предупреждение.
- Исходные метаданные /model описывают LogisticRegression и 14 признаков,
  фактический model.txt — LightGBM с 15 признаками; evaluate возвращает
  risk_scorecard_v1.0. Эти строки не исправляются интеграцией. В БД сохраняется
  версия, заявленная сервисом, а образ фиксируется SHA Git-коммита.
- Новости и реквизиты компаний — синтетические. БКИ не запрашивается реально.

## Заявки и решения

Черновик сохраняется в БД. Отправка фиксирует SUBMITTED → CHECK → ENRICH →
SCORING. Сетевой вызов не держит write-транзакцию SQLite.
Стоп-фактор либо score < 520 → REJECTED; score ≥ 620 и сумма в пределах
посильного лимита → APPROVED; остальные случаи → REVIEW.
Таймаут/невалидный ответ ML → REVIEW и scoring_unavailable=true без выдуманных
показателей. Сотрудник в REVIEW может одобрить, отказать, запросить сведения или предложить встречные условия; причина обязательна.
Клиенту не выдаются внутренние score/PD, коды стопов и пороги политики.

Проверяется владелец заявки и роль сотрудника. Статус нельзя изменить через
PATCH. Idempotency-Key (UUID) предотвращает дублирование POST создания заявки;
повторная отправка завершённой заявки не вызывает ML повторно. Зависшую более
30 с SCORING можно повторить через тот же submit: новый request_id исключает
запись запоздавшего результата. Одновременное редактирование/отправка
защищены проверкой updated_at; при конфликте возвращается 409.

Реализованы офферы, встречные условия, PDF/XLSX, дозапрос, PDF-договор, демонстрационные подписание и выдача. Подробности: STATES.md и TEST_SCENARIOS.md.
APPROVED здесь означает одобрение заявки, а не подписание или выдачу средств.

## Проверка

`python -m pytest` проверяет владение, роли, валидацию, повторные запросы,
конкурентное изменение, восстановление SCORING, ручное решение и сбои ML.
Для реального сервиса задать `ML_INTEGRATION=1` и ML_BASE_URL, затем pytest.
CI собирает ml/ без изменений через deploy/Dockerfile.ml с отдельным deploy/ml-constraints.txt, запускает контейнер и проверяет
pre-predict/evaluate всех трёх компаний перед production-деплоем.

В браузере: войти → новая заявка → дождаться оценки → отправить → открыть
историю → перезагрузить страницу. Войти сотрудником → открыть ту же заявку.
Для ручной ветки выбрать профиль ИП Смирнов и параметры с высокой нагрузкой;
фактический маршрут зависит от результата модели, а не названия демо-профиля.

Сервер: сохраняются /opt/alfa-potok/data и администратор. Перед миграциями
создаётся SQLite backup. last-good-compose.yaml позволяет откатить и состав
контейнеров, включая переход со старой конфигурации из двух сервисов.

Версии Linux-окружения зафиксированы вне ml/ в deploy/ml-constraints.txt.
Проверка неизменности: `git diff --exit-code 50af371 -- ml`.
