# AI-консультант по кредитным продуктам

Модуль `backend/api/consultant.py` принимает описание задачи предпринимателя
и асинхронно вызывает `/v1/chat/completions`. В интерфейсе он находится в
разделе **Продукты**. Кнопка «Перейти к заявке» переносит рекомендованный
продукт, срок и исходное описание задачи в форму; отправка заявки остаётся
явным действием клиента.

## Подключение

Параметры задаются окружением процесса. Локально Django также читает
`backend/.env`; окружение имеет приоритет. Docker Compose читает корневой
`.env` и передаёт параметры backend-контейнеру.

```dotenv
LLM_BASE_URL=http://internal-jury-llm-host:8000/v1
LLM_API_KEY=jury_token
LLM_MODEL_NAME=qwen2.5:7b
LLM_TIMEOUT_SECONDS=5.0
```

По умолчанию LLM_BASE_URL пустой: сервис сразу подбирает продукт по
ключевым словам без сетевых обращений. Жюри задаёт три параметра выше
в корневом `.env` и запускает `docker compose up --build`; дополнительного
переключателя нет. Веса и контейнер LLM не входят в проект, не скачиваются
и не разворачиваются. В Compose ровно три сервиса: Django со сборкой Vue,
FastAPI скоринга и PostgreSQL. Общие лимиты памяти — менее 1 ГиБ.

Ключ не хранится в Git, не передаётся браузеру и не выводится в логах.

Для vLLM/llama.cpp или сервера жюри замените BASE_URL и MODEL_NAME на адрес
OpenAI-совместимого сервера и имя развёрнутой модели. Для внешнего шлюза
задайте также его ключ. Код консультанта не зависит от конкретного провайдера.
Используется путь `<LLM_BASE_URL>/chat/completions`, температура `0.1`,
`stream=false`, четыре few-shot примера. Запрос не использует специфичные
для провайдера форматы structured output.

## API

`POST /api/v1/consultations/` — авторизованный клиент, заголовок
`Authorization: Token <token>`. Сотрудник банка не вызывает клиентский подбор.

```json
{"user_query":"Нечем платить зарплату завтра, клиент задерживает расчет"}
```

Длина после удаления краевых пробелов — 5–1000 символов. Другие поля
запроса отклоняются; параметры подключения задаются только сервером.

```json
{
  "product": "overdraft",
  "confidence": 0.96,
  "title": "Овердрафт",
  "explanation": "Овердрафт поможет закрыть временный кассовый разрыв. Поступление оплаты от клиента позволит восстановить доступный лимит.",
  "suggested_term_months": 2,
  "alternative_product": "working_capital",
  "is_fallback": false
}
```

Коды и горизонты консультации:

- `overdraft` — кассовые разрывы и ожидаемые поступления, 1–3 месяца.
- `working_capital` — товар, сырьё и сезонный склад, 6–24 месяца.
- `equipment_purchase` — техника и производственное оборудование, 12–60 месяцев.
- `investment` — новые точки, ремонт и строительство, 24–120 месяцев.

Рекомендация выбирает продукт. Дальнейшее решение по заявке принимает
кредитный конвейер. `confidence` относится к классификации задачи.

## Проверка ответа и резервная ветка

Сервис извлекает регулярным выражением фрагмент от первой `{` до последней
`}`, разбирает JSON и валидирует `ProductConsultationResponse` через Pydantic.
Проверяются допустимые коды, числовой confidence 0–1, целочисленный срок
в диапазоне продукта, русскоязычные название и объяснение из 2–3 предложений,
отличие альтернативы от основного продукта. Лишние поля и обещания
гарантированного одобрения отклоняются.

Сеть, HTTP 4xx/5xx, неверный JSON, неизвестный продукт, неверная структура,
слишком большой ответ или выход за общий срок включают встроенный
rule-based fallback. Кассовые разрывы/зарплата/задержка оплат дают overdraft,
товар и сырьё — working_capital, станки и оборудование — equipment_purchase,
новые точки/ремонт/строительство — investment. Неопределённая задача —
working_capital. Ответ имеет confidence=0.0, is_fallback=true и остаётся
валидным по общей схеме. Клиент продолжает тот же сценарий без прерывания.
Недопустимый ввод — 400, отсутствующий вход — 401, другая роль — 403,
превышение частоты обращений — 429.

Общий бюджет вызова ограничен `min(LLM_TIMEOUT_SECONDS, 5.0)` с помощью
`asyncio.timeout`; HTTPX дополнительно ограничивает сетевые операции.
Повторных сетевых попыток нет. Ответ ограничен 64 КиБ, перенаправления
отключены. Логи содержат код выбранного продукта или класс ошибки, без
запроса, исходного ответа, адреса провайдера и ключа.

## Использование из Python/FastAPI

```python
from api.consultant import consult_product

result = await consult_product("Закупаем партию обуви на осенне-зимний сезон")
payload = result.model_dump(mode="json")
```

Модуль не импортирует Django и использует только httpx/Pydantic и стандартную
библиотеку. При отдельном запуске добавьте backend в PYTHONPATH; .env можно
загрузить через `dotenv.load_dotenv`. Django-адаптер вызывает эту же coroutine
через `async_to_sync`, сохраняя существующие аутентификацию и API сайта.

## Проверка

`python -m pytest backend/api/test_consultant.py` проверяет контракт HTTP,
четыре продукта, few-shot примеры, обёртки JSON, неизвестные значения,
несоответствующие типы, сбои, реальный пятисекундный дедлайн, медленный поток,
асинхронное выполнение нескольких запросов, вход, роли и перенос инвестиционного
срока 120 месяцев в заявку. Сетевые ответы в unit-тестах контролируются
`httpx.MockTransport`; они проверяют интеграционный контракт.

Для проверки самой подключённой LLM вызовите API с двумя запросами из ТЗ:
зарплата/задержка расчёта → `overdraft`; сезонная партия обуви → `working_capital`.
Для проверки выключенного LLM остановите только его собственный экземпляр
или задайте неиспользуемый localhost-порт и проверьте `is_fallback=true`
за время не более 5.1 секунды.

Документация протокола и библиотек:
[HTTPX AsyncClient](https://www.python-httpx.org/async/),
[Pydantic validators](https://docs.pydantic.dev/latest/concepts/validators/),
[Ollama OpenAI compatibility](https://docs.ollama.com/api/openai-compatibility).
