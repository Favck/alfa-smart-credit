Сквозное взаимодействие: сбор признаков, скоринг риска, Explainability для андеррайтера и машина состояний.
Бэкенд · Django

Оркестратор конвейера

  • Хранит заявку и машину состояний
  • Берёт данные из моков ЕГРЮЛ / БКИ

  • Обеспечивает экран андеррайтера (REVIEW)

Движок оценки риска

  • Правила-стопы (просрочки, ликвидация)
  • Скоринговая модель (скоркарта / LightGBM)
  • Расчет Explainability (SHAP / веса причин)
  • Расчет посильной суммы (max_limit)
  • Не ходит в БД и внешние сервисы
  • Не принимает кредитное решение

Что идёт туда (Django → FastAPI: POST /score)

  • Идентификаторы: application_id, request_id (сквозной трейсинг)
  • Параметры заявки: продукт, запрошенная сумма, срок
  • Финансовые метрики: заявленная выручка, текущие платежи, расчетный DTI
  • Данные обогащения (ЕГРЮЛ): возраст бизнеса (мес.), отрасль (ОКВЭД), статус
  • Данные БКИ: наличие истории, число закрытых кредитов, просрочки (0 / 30 / 90+)

Что идёт обратно (FastAPI → Django: 200 OK)

  • Оценка риска: score (300–850), pd (вероятность дефолта, 0.0–1.0), risk_grade (A, B, C, D)
  • Стоп-факторы: stop_factors: [] (если сработали — код и описание, напр. "BKI_OVERDUE_90")
  • Explainability (факторы скоринга): структурированный список топ-3…5 драйверов для экрана андеррайтера
  • Посильная сумма: max_limit (максимальная сумма кредита, если запрошено слишком много)
  • Служебное: model_version, calculation_time_ms

Объяснение для пользователя и андеррайтера (Explainability)

Формат передачи факторов:

ML отдает структурированный массив. Бэкенд и фронтенд отображают его: клиенту — понятными словами, андеррайтеру — в виде графика плюсов и минусов к базовому баллу.

Пример факторов (Explainability)
Долговая нагрузка выше нормы (DTI > 50%)−40
Положительная история в БКИ (нет просрочек)+60
Стабильный возраст бизнеса (4 года)+40
Длинный срок кредита (24 мес.)−10

Если ML-сервис недоступен (Отказоустойчивость)

Таймаут вызова ML — 2.5 секунды. Если сервис упал или не ответил вовремя, бэкенд не падает с 500 ошибкой, а переводит заявку в статус REVIEW с системным флагом scoring_unavailable: true для ручной оценки андеррайтером.

Пайплайн одной заявки (дерево переходов)

БЭК делает бэкенд · ML делает ML-сервис · КЛ действие клиента
КЛ Выбрал компанию и отправил заявку
└─ БЭК Сохранил заявку → SUBMITTED
   └─ БЭК Проверка полноты → CHECK
      ├─ не хватает обязательных полей → NEED_INFO → КЛ догружает → возврат в ENRICH / REVIEW
      └─ форма валидна → ENRICH
         └─ БЭК Моки ЕГРЮЛ + БКИ → собрал признаки
            └─ БЭК Запрос POST /score в ML → SCORING
               ├─ ML 1. Валидация схемы данных Pydantic
               ├─ ML 2. Проверка правил-стопов (ликвидация, дефолт БКИ)
               │   ├─ стоп сработал → ответ с stop_factors
               │   └─ стопов нет → шаг 3
               ├─ ML 3. Модель → score, PD, grade
               ├─ ML 4. Explainability → топ-3…5 факторов с баллами и текстом
               ├─ ML 5. Расчет max_limit → ответ Django
               │
               ├─ ML упал / таймаут → БЭК ручной разбор → REVIEW
               └─ ML ответил 200 OK → БЭК Сохранил ScoreResult, применил матрицу решений:
                  ├─ [Зеленый] типовой автоскоринг → APPROVED → генерация оффера
                  ├─ [Красный] критический стоп-фактор → REJECTED (мотивированный отказ)
                  └─ [Желтый] пограничный случай / крупная сумма → REVIEW (Экран андеррайтера)
                     ├─ Андеррайтер: Одобрить → APPROVED
                     ├─ Андеррайтер: Скорректировать лимит → COUNTER_OFFER
                     │   ├─ КЛ Согласен со встречными условиями → SIGNING
                     │   └─ КЛ Отказался от встречных условий → CANCELLED
                     ├─ Андеррайтер: Запросить выписку/документ → NEED_INFO
                     │   └─ КЛ Загрузил документ → возврат в ENRICH / REVIEW
                     └─ Андеррайтер: Отклонить с причиной → REJECTED
                        └─ КЛ Ознакомление с договором → ПЭП (подписание) → SIGNING → DISBURSED (Выдано)

Зоны ответственности и стек

ML (FastAPI)
  • Синтетический датасет и воспроизводимый скоринг
  • Модель: скоркарта / LightGBM с расчетом PD и Score
  • Расчет Explainability (SHAP / вклады весов)
  • Расчет безопасного лимита (max_limit)
  • Pydantic-валидация и эндпоинт /score
  • Легковесный Dockerfile без тяжелых GPU/Deep Learning библиотек
Не делает: не трогает БД, не принимает финальный статус, не держит LLM
Бэкенд (Django)
  • Готовые демо-аккаунты (сид 3 профилей в БД)
  • Машина состояний заявки и аудит переходов
  • Моки внешних систем (ЕГРЮЛ, БКИ)
  • Экран андеррайтера (разбор пограничных заявок)
  • Решение конвейера: матрица переходов по скорингу
  • Генерация договора и эмуляция выдачи (DISBURSED)
  • Интеграция LLM (в субботу): клиент к OpenAI-compatible API через .env
Не делает: не считает математический риск сам, не меняет логику модели
